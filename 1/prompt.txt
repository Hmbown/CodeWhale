# 3. How the catalog is built; visible vs searchable-only

Two layers.

**Layer 1 — registry → API tools (`model_visible`).**
`ToolRegistry::to_api_tools` (`crates/tui/src/tools/registry.rs:245-249`) memoises `build_api_tools` (`registry.rs:258-301`). It sorts by name (prefix-cache stability), then filters `tool.model_visible()` (`registry.rs:272`), then read-only-authority and network filters (`registry.rs:273-282`), then emits `models::Tool { …, defer_loading: Some(tool.defer_loading()), … }` (`registry.rs:295`). A tool with `model_visible() == false` is registered and executable by name (saved-transcript replay) but never advertised — e.g. `rlm` (`crates/tui/src/tools/rlm.rs:167`), `exec_shell` (`crates/tui/src/tools/shell.rs:4406`), the `todo_write` aliases (`registry.rs:1343-1367`).

**Layer 2 — catalog shaping (`defer_loading`).**
`build_model_tool_catalog_with_surface` (`crates/tui/src/core/engine/tool_catalog.rs:183-206`), called from `crates/tui/src/core/engine.rs:4178`:
1. `apply_native_tool_deferral` (`tool_catalog.rs:139-143`) → `should_default_defer_tool` (`tool_catalog.rs:124-137`).
2. `apply_mcp_tool_deferral` (`tool_catalog.rs:145-157`) — every MCP tool is deferred unless in `tools_always_load`.
3. `apply_tool_surface_budget` (`tool_catalog.rs:234-249`) — `Compact` budget additionally defers `Run`, `tasks`, `Web`.
4. `ensure_advanced_tooling` (`tool_catalog.rs:271+`) injects the synthetic `tool_search` entry with `defer_loading: Some(false)` (`tool_catalog.rs:350`).

**The controlling struct/field:** `crate::models::Tool` and its field `defer_loading: Option&lt;bool&gt;` (set at `registry.rs:295`, overwritten at `tool_catalog.rs:141`, `154-156`, `247`). The trait-level defaults are `ToolSpec::defer_loading()` (`crates/tui/src/tools/spec.rs:1412-1414`, default `false`) and `ToolSpec::model_visible()` (`crates/tui/src/tools/spec.rs:1420-1422`, default `true`). Only three concrete overrides of `defer_loading` exist: `crates/tui/src/tools/read_media.rs:222` (`true`), `crates/tui/src/tools/registry.rs:1498` (MCP adapter: defer unless a discovery helper), `crates/tui/src/tools/dynamic.rs:45` (from the dynamic spec).

**Initially visible** = present in the catalog with `defer_loading != Some(true)`, i.e. it lands in `initial_active_tools` (`tool_catalog.rs:357-371`). In practice: `read, write, edit, bash, agent, todo_write, tool_search`.
**Searchable only** = in the catalog with `defer_loading == Some(true)`; the schema is withheld until `tool_search` returns a `tool_reference` and `execute_tool_search_inner` (`tool_catalog.rs:1273-1355`) inserts the name into `active_tools`. Activation is bounded by `ToolActivationCache` — 8 names / 16 KiB of added schema (`crates/tui/src/core/session.rs:17,19`, `activate` at `session.rs:99`); over-budget matches come back as `unavailable_tool_references` (`tool_catalog.rs:1338-1344`).

Sub-agent children have their own copy of this pipeline: `deferred_catalog_for_model` (`crates/tui/src/tools/subagent/mod.rs:14702-14720`) and `execute_from_surface` hydrate/activate path (`mod.rs:14893-14930`).
